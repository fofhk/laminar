# 撤单/偏斜逻辑草图（方向 A 无标签发现 → Stage 2 设计输入）

日期 2026-08-22 · 状态 **草图，未实施、未测试** · 关联 `laminar_20260814_preregistration.md`、
`worklogs/2026-08-22_laminar-direction-a-unlabeled_v1.md`

这是一份设计草图，不是 Stage 2 规格。目的是把今天的发现（大单之后价格朝原方向显著延续）
翻译成一条具体的做市逻辑，供下周中价版本验证后细化——**现在不实现、不回测、不改
`src/laminar` 任何生产代码**（Stage 1 无签名无下单，这条草图本身也不需要改变这一点）。

## 前提（今天的发现，原样引用，不重新论证）

大单（≥$1,000 notional）之后 5–240 分钟，成交价朝下单方向显著延续（t = 3.06–4.23）；
小单反方向（均值回归/买卖价差反弹）。效度威胁（无中价数据、覆盖率随时限收窄等）见来源 worklog，
这里全部沿用，不重复。

## 要防的风险，用做市商的话说

一笔大单印花之后，如果价格确实会朝那个方向继续走，我方在**被动一侧**的挂单就处在逆向选择里：
大买之后价格上涨，我方的 ask 更容易被下一波买盘继续吃到，且吃到的价格比"公允价"更差；
大卖同理伤 bid。这正是预注册"Honesty notes"里点名"Stage 2 must model adverse selection before
any order is sized"要建的那块模型的第一个具体触发条件。

## 逻辑草图

**触发**：本方 watchlist 内某 token 上出现一笔 notional ≥ `LARGE_USD` 的成交（不要求打在我方挂单价位上——
今天的度量是"整体价格延续"，不是"我方被打穿"，触发条件应该更宽，覆盖"市场要往哪走"这个信号本身）。

**响应**（分三档，从轻到重，具体用哪档待下周中价结果定）：

1. **偏斜（skew）**：把参考中价的双边报价，往大单方向整体挪一点——大买之后，ask 报得更贵（更难被
   继续吃）、bid 相应也抬高（不然两边offset不对称会破坏 `max_spread` band 内的双边资格）。
   这是最省成本的一档：仍在 `max_spread` 带内、仍拿 reward，只是让被动一侧的成交价更贵一点。
2. **减量（resize）**：暴露一侧（大买之后是 ask 侧）的挂单量下调，但不低于 `min_size`（否则那一侧
   直接归零拿不到 reward）——保留资格、降低单次逆向选择的名义敞口。
3. **撤单（cancel）**：暴露一侧直接撤下，接受那一侧当次 reward 归零，换取不被继续吃。最重的一档，
   只在信号最强/延续幅度最大时用。

**持续时间**：今天的数据里，延续效应在 5–15 分钟最强（t=4.22/4.23），60–240 分钟仍显著但没有继续放大——
草图倾向于响应窗口设在 **15–60 分钟**，之后线性或阶梯式撤回到默认报价，而不是设一个固定不动的偏斜。
这是一个待校准的参数，不是结论。

## 必须先解决、现在没有答案的三件事

1. **阈值不该是死的 $1,000**：今天为了能和"606 笔 ≥$1k"这个已有基准对齐，用了统一美元门槛，
   但 30 个 watchlist 市场的 `daily_rate`（77–500 USDC/day）和書面深度差异很大，同一个 $1,000
   在薄市场和厚市场里的信息含量不该一样。真正的草案应该按**市场自身成交额分布的分位数**定阈值，
   而不是照抄今天探索用的绝对值。
2. **偏斜/撤单是有代价的，代价还没有算过**：`score.order_score` 对 `s > max_spread` 或
   `size < min_size` 是硬性归零，不是渐进衰减——偏斜或撤单每往外挪一步，就在向"完全牺牲这一侧的
   reward"的悬崖靠近。今天核实的年化 gate（`worklogs/2026-08-22_laminar-yield-gate-check_v1.md`）
   算的是**静态、不做任何防御动作**下的毛收益（中位数 260–365%，最差 27.8%）；这份草图要花的正是这块
   收益的一部分去换取更低的逆向选择敞口，但换多少、值不值，现在完全没有量化，是这份草图最大的缺口。
3. **没有中价，就没法准确定义"偏斜了多少"**：草图第一档说"把参考中价挪一点"，但今天的发现是用成交价
   算的，不是书面中价——严格来说还不知道书面中价是否真的跟着延续，还是只是买卖两侧成交打印的机械交替
   （见来源 worklog 效度威胁第一条）。下周中价版本出来之前，这份草图里"挪多少"这一步没法定数字。

## 明确不做的事

- 不写任何下单/撤单/签名代码——Stage 1 没有 CLOB 鉴权，这份草图也不应该成为绕过这一点的理由。
- 不回测——calibration window 的数据不能拿来当"这套逻辑历史上会赚多少钱"的证据，那需要 holdout
  窗口（08-14 起）且需要真实成交模拟，两者现在都不具备。
- 不并入方向 B（带标签、按钱包分类）——这份草图完全不依赖钱包身份，只用"这一笔多大"，和方向 B
  是两条独立的线。
