- 日期:2026-09-17(采集机 UTC)
- 版本:v1

- 交付:`src/laminar/reconcile.py`(新)、`tests/test_laminar_reconcile.py`(新,11 项)

## 1. 要回答的问题

V1 证明的是**代码自洽**:我方订单等于整本展示簿时,成交流水必须逐笔落在我方,
5,148 笔零误差。那是关于代码的陈述,不是关于世界的陈述。

V2 问世界一个问题:

> 一笔成交吃掉深度之后,下一个快照里,那部分深度**真的没了吗**?

- 如果基本没了 → 簿子在 1 分钟尺度上接近"只出不进",`shadow.size_ahead` 里
  "我前面的显示量"是一个稳定的障碍,前/后队列双界成立。
- 如果一分钟内就被撤掉或补上 → **"前面的量"不是稳定障碍**,队尾就不是悲观边界。
  这正是 `docs/OPEN_QUESTIONS.md` 第 1 条自己写下的疑问。

## 2. 方法

观测单位 = 一个 token 相邻两次快照之间的区间 `(tb, ta]`,按被吃的一侧分离。
对该侧在该区间内的所有成交:

```
consumed    = 该侧成交量之和
deepest     = taker 触及的最远价位(买侧取最低成交价,卖侧取最高成交价)
depth_*     = 价格不劣于 deepest 的挂单量,取快照 tb / ta
drawdown    = depth_before - depth_after
```

该侧每一笔成交的价格都不劣于 `deepest`,所以 `consumed` 恰好是这段深度必须吸收的量。
四种结果:

| 分类 | 判据 | 含义 |
|---|---|---|
| `accounted` | `drawdown == consumed` | 簿子只出不进 |
| `under` | `drawdown < consumed` | 一分钟内深度被补回 |
| `over` | `drawdown > consumed` | 我方之前的深度被**撤掉**(与成交无关) |
| `no_depth` | `depth_before == 0` | 成交打在从未记录的价位上(60 秒盲区) |

容差取 `max(1 股, 1% × consumed)`。用 `books_full`(全深度)而非带内序列——
扫过奖励带之外的成交正是带内数据无法对账的那部分。两个快照相隔超过
`MAX_GAP_MS = 180s` 的区间直接丢弃,不猜。

## 3. 全窗口结果(08-25 → 09-17)

| 分类 | 区间数 | 占比 |
|---|---|---|
| `accounted` | 4,464 | **19.7%** |
| `under`(补回) | 6,574 | **29.1%** |
| `over`(撤单) | 5,728 | **25.3%** |
| `no_depth`(盲区) | 5,846 | **25.9%** |

- 合计消耗 16,624,136 股,深度减少 18,648,411 股,**recovery = 1.122**
- 逐日 recovery 中位 1.034、最低 0.720、最高 1.746(逐日波动大,因为它是总量比值;
  分类占比才是稳定统计量)
- 逐日分类占比很稳:`accounted` 13–29% · `over` 21–36% · `under` 22–36% · `no_depth` 19–30%

## 4. 它推翻了什么

**成立的那个前提不成立。** 只有约 **1/5** 的区间是纯粹"成交吃掉深度、深度就不见了"。
- **约 1/4 的区间,深度减少超过成交量**。净减少里超出的那部分只能来自撤单,
  即排在我方前面的量**在没有成交的情况下消失了**。这会让队尾的单凭空前移,
  所以 **`QUEUE_BACK` 不是悲观边界**——它把一个会被撤掉的障碍当成了稳定障碍。
- **约三成区间深度被补回**,说明一分钟尺度上挂撤频繁,静态簿子不是稳定队列。
- **约 1/4 的区间打在未记录的价位**,与 V1 测得的 60 秒盲区同量级,互相印证。

结论:**`shadow.py` 的 front/back 双界是"两个可达极端",不是"真值的包络"。**
下游任何引用成交率区间的地方,都必须把 V2 的 `over`/`under` 比例作为
**第二维不确定性**一起报告,不能只报队列取前端/后端的差。

## 5. 口径限制(先于结论读)

1. **首要替代解释:成交流水可能不完整。** 采集器每小时分页抓取 `data-api/trades`,
   若漏抓,`consumed` 会被低估,而 `drawdown > consumed`(over)会被**系统性高估**。
   在把 `over` 当作"撤单"之前,必须先用成交完整性核查排除这一点。
   这是本节最重要的限制,未排除前 §4 的 over 只能读作"深度减少 > 已记录成交量"。
2. **净额无法区分撤单与补单。** 区间级净额把"先补后撤""先撤后补"抹平;
   `under`/`over` 是净方向,不是事件计数。
3. **整段用最远价位汇总**,段内先后顺序被抹平。若一段内先深后浅,汇总会失真。
4. **跨小时边界的区间未对账**(逐小时分区加载,1 vCPU/961MB 无法整天载入),
   每天损失约 20 个区间,占当日 2–3%。
5. **09-17 为不完整日**(仅 7 个分区),不进占比统计的解读基线。

## 6. 影响与下一步

- 对 Stage 1 奖励数学**无影响**(`bounds_sweep` 不经过撮合);影响的是
  **成交率与成本层**,进而影响净年化的可信区间。
- 建议的 V2.1:**按价格档**做增量对账(而不是按最远价汇总),并加一项
  **成交完整性核对**——用同一 tx 的链上/活动数据交叉验证流水是否漏抓。
  只有完整性成立后,`over` 才能被正式命名为"撤单导致的队列前移"。
